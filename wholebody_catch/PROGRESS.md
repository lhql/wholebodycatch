# wholebody_catch 开发记录

## 2026-10-11：无标记感知与允许遮挡的预规划抓取

当前默认：SAM 2.1 tiny 分割 + 对齐深度生成侧向抓取点，曝光位姿转换、卡尔曼关联；预抓取时生成平滑接近轨迹，默认冻结终点。无需强化学习，最后一段允许不再看到物体；末段盲行限制 4.5 cm / 最后观测后 5 秒，超出范围或跟踪偏差过大则短距离回退重观测。闭爪后可用持续双侧接触和末端抬升验证，不强制视觉重现，有视觉时要求其一致。

已增加：独立 Python 3.11 GPU 推理进程和可复现下载脚本；RGB-D/曝光 TF 实机感知入口；可替换触觉输入；球/方块/圆柱随机尺寸、颜色、位置场景生成器。当前执行器适配器仍复用 PX4 与五轴全身控制，实机需标定相机 TF、工具抓取中心并对接驱动。

控制改进：近目标处根据实测机体速度分配机械臂补偿，机体参考阻尼；双指参考相对编码器最多压入 0.8 mm；接触去抖保留失联超时；工具抓取中心相对指尖 TCP 后移 24 mm。增加起飞等待超时、遥测失效、降落请求超时保护。旧红球检测器保留 `perception:=sphere` 基线。

已执行：colcon 构建通过；22 项源码算法测试通过，覆盖平滑轨迹峰值速度、短时失去图像仍完成闭爪/抬升、盲行超时与跟踪误差退出、预测不伪造观测、目标关联、部分可见时冻结终点；ROS 接口检查通过；三类场景源 XML 和 Python/脚本语法检查通过。系统 ROS Python 3.8 与推理 Python 3.11 分离，未分析工作区编译产物。

物理验证历史（Gazebo/PX4 + FastLIO2，控制无真值输入）：

- 早期已知红球试验分别出现闭爪超时、边缘裁切失去观测、接近定位精度不足；保留 `docs/validation/` 历史失败报告。
- 第 7–8 轮获得双侧接触但未完成抬升，定位到接触时序与指尖边缘夹持问题；第 9 轮 SAM 2 浮点掩码类型错误，已修复。
- 第 10 轮 SAM 2 动态修正终点，真实最大抬升 1.53 cm 后滑落，任务中止，独立验收失败。近距离部分可见使抓取点向上漂移。
- 第 11 轮采用当前默认冻结终点，**独立物理验收通过一次**：真实最大抬升 15.98 cm，验收末样本抬升 15.29 cm，物体距 TCP 1.84 cm，双侧接触及真实持物满足连续 2 秒。此轮视觉仍可见，不算遮挡物理验收。
- 第 12 轮改为蓝色无标记方块，随机种子 7，位置和尺寸均不同。在仿真时间 73.699 秒、轨迹剩余 1.846 秒时暂停感知节点；74.256 秒进入 `planned_blind`，76.105 秒闭爪（观测已过期 2.783 秒），86.437 秒进入 `SUCCESS/contact_and_tool_motion`（已 13.115 秒无新目标观测）。**独立物理验收通过一次**：最大真实抬升 16.45 cm，末样本抬升 15.73 cm，物体距 TCP 1.70 cm，双侧接触连续满足 2 秒。感知进程在成功后恢复，试验结束后关闭本次仿真。

报告索引：`docs/validation/development_trials.json`；原始真值报告以 `.json.gz` 保存，方块场景与中断事件另存于同目录。球和方块各一次通过不是重复成功率。圆柱目前只做场景生成检查；实机、未知杂乱物体、完整碰撞规划、动态目标抓取及长期持物尚未验证。可见表面启发式不等于恢复完整物体几何或保证力闭合。
